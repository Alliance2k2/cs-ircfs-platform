# Repository audit — October 2026

The baseline for the modernization work on branch `feature/platform-modernization`. It records what the platform already does, what was found broken or risky, and how the code compares with the CS-IRCFS proposal ([architecture.md](architecture.md)).

## Architecture as found

```text
Feature phones ──USSD *801# / SMS 8448──► Africa's Talking ──► FastAPI (backend/app)
                                                                 │  16 routers, ~70 endpoints
                                                                 │  services: ussd, sms_keywords, advisory, forecast,
                                                                 │  analytics, reporting, cases, notifications, cooperatives
                                                                 ▼
                                                    PostgreSQL/PostGIS (SQLite for local work)
                                                    Alembic migrations 01–15
                                                                 │
                     dashboard/ (17 static HTML pages, vanilla JS, Bootstrap 5, Leaflet)
                     served by FastAPI at /
```

- **Backend:** Python 3.11+, FastAPI, SQLAlchemy 2, Pydantic 2, Alembic, GeoAlchemy2, slowapi. 91 tests passing at the start of the audit (in-memory SQLite, telecom forced to dry-run).
- **Frontend:** `dashboard/`, no build step. Shared helpers in `assets/js/shared.js` (API access, session, EN/RW dictionary) and `app-shell.js` (sidebar from one `GROUPS` list). `app.js` (940 lines) drives eight dashboard pages through `<body data-page>`; `management.js` (790 lines) drives Platform Management.
- **Styles:** up to eight overlapping stylesheets per page (`styles.css`, `overrides.css`, `shared.css`, `planner-extra.css`, `dashboard-theme.css`, `app-shell.css`, …), with separate sets for management, the backend console, the simulator, sign-in and the landing page. This is the visual inconsistency the brief describes.
- **Deployment:** `Dockerfile` (single stage), `render.yaml`, `infrastructure/docker-compose.yml` with PostGIS. No CI.

## Defects and risks found

| # | Severity | Finding | Status |
| --- | --- | --- | --- |
| 1 | Critical | `slowapi` imported but missing from `requirements.txt`: a fresh Docker or Render build crashes at startup | Fixed |
| 2 | Critical | Open self-registration created **active** monitor accounts that could read phone numbers, message text and household nutrition records | Fixed: accounts start pending; masking and staff-only nutrition records |
| 3 | High | USSD/SMS callbacks unauthenticated: anyone could post forged reports | Fixed: callback secret, optional IP allow-list |
| 4 | High | Grievance anonymity broken by the message logs: the inbound log and SMS acknowledgement tied the sender's phone to the grievance reference | Fixed (see [security.md](security.md) for the remaining timing caveat) |
| 5 | High | Rate limits per IP with no proxy headers: on Render every client shares one address, and all real gateway traffic comes from a few addresses | Fixed: proxy headers; per-phone limit for callbacks |
| 6 | Medium | Production guard did not require secure cookies, a clean CORS list or a callback secret; no security headers | Fixed |
| 7 | Medium | Simulator tests and seeded demo rows were indistinguishable from field reports; the simulator could trigger real SMS and airtime when providers were live | Fixed: `data_origin`, simulator dry-run |
| 8 | Medium | "Faulty or offline assets" counts every fault report ever received, not the assets currently down | Fixed in the new executive overview (latest status per asset); legacy figure relabelled |
| 9 | Low | Sign-in `next` redirect only accepted `x.html` pages | Fixed for `/app/` paths |
| 10 | Low | No CI; PostgreSQL migrations only exercised by hand | CI workflow added (tests, PostGIS migrations, frontend checks, Docker build); it first runs when the branch is pushed |
| 11 | Low | `scope.case_cell` looked up infrastructure cases in the wrong table (unused, so no effect) | Removed |

## Compared with the proposal

Every module in the proposal's architecture has a working implementation (see the coverage table in [architecture.md](architecture.md)). The gaps are not missing features but missing evidence and polish:

- Official PADAB/APEFA yield baselines, calibrated rainfall thresholds and asset inventories still need to be entered from source documents.
- Live telecom delivery awaits Africa's Talking production credentials and a short code.
- The Kinyarwanda screens need native-speaker review.
- The dashboard is functional but visually fragmented, and has no dedicated workspaces for evaluation, climate or geography.

The plan and progress for closing these gaps are in [remaining-work.md](remaining-work.md).
