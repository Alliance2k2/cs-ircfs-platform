# Assistant security review and remaining gates

The assistant reads knowledge, never field records or arbitrary filesystem paths.
Document-management writes affect only its dedicated knowledge tables. No live-data
connector, SQL generation, SMS, airtime, report editing or autonomous action exists.
Future operational lookup must use explicit read-only backend services that take the
authenticated `Principal`, enforce geography and return minimal typed aggregates;
it must never accept SQL generated by a model. That interface is not enabled here.

| Threat | Implemented controls | Remaining limits |
| --- | --- | --- |
| Unauthorized/cross-user knowledge | Staff ask; admin management; approved versions; role/required-sector checks before chunk selection | Administrators are trusted reviewers; institutional approval must be real |
| Direct/indirect injection | Request patterns; untrusted-context prompt; no tools; verbatim evidence validation and fallback | Patterns/prompt cannot prove resistance; poisoned source content and selective quotation can look plausible |
| Personal/secret disclosure | Existing phone/email/key patterns; no participant indexing; no managed source sent externally | Names/unusual identifiers/secrets can evade detection; generation stays off |
| Malicious uploads | Off by default; admin only; streaming size cap; bounded format/ZIP/XML handling; no macros/URL fetching | PDF parsing is not a CPU/memory sandbox; isolated worker required before deployment activation |
| Cross-site mutations | Same-origin Origin checks; existing cookie/auth restrictions; no wildcard CORS | Reverse-proxy origin configuration needs staging acceptance |
| Resource exhaustion | 64 KiB streaming JSON cap; request/history/file/text/page/chunk/candidate/context limits; rate limits; bounded provider output/time/retry; lexical fallback | IP limits are not per-user/distributed budgets; DB metadata scan is pilot scale |
| Output execution | React text rendering, no dangerous HTML/Markdown renderer | Source text still requires human judgment |
| Logs | Counts, timing, mode, fixed provider/prompt version, usage counts, categorical feedback only | Configure protected log access/retention; upstream HTTP access logs must not record document metadata query strings |

Required-sector policy uses **all required sectors**: a document containing data for
sectors 1 and 2 cannot be shown to an account limited to sector 1. General procedures
have an empty required-sector list. Roles are explicit, including administrators;
being an administrator does not bypass a document's retrieval ACL. Service API keys
retain existing district-wide semantics and must not be granted unnecessarily.

Deletion physically removes chunk text and vectors and revokes retrieval immediately;
metadata and approval references remain. Backups and application logs follow their
own retention policies. No promise of universal irreversible erasure is made.

Approval references, titles and uploaded text must exclude personal data. Failed
extraction returns generic parser errors, not document text or provider payloads.
No credentials, personal files, institutional datasets or real grievance content
were used for tests. The local parser install fetched only a public package.

Before real use: isolate parsing; review administrator policy and source permissions;
test PostgreSQL/vector concurrency; complete native language review and red teaming;
validate claim support; review provider processing and spending separately. Do not
interpret passing mocked tests as production readiness.
